# Windows driver tracing through QEMU

Linux `usbmon` observes the host transactions generated by QEMU USB passthrough.
This records the official Windows driver's behavior without adding USB capture
software to the guest.

## Host prerequisites

```bash
sudo pacman -S --needed qemu-desktop edk2-ovmf swtpm wireshark-cli
```

Configure `dumpcap` according to the Arch package prompts so the local user can
capture packets. Load `usbmon` if its interfaces are not listed:

```bash
sudo modprobe usbmon
dumpcap -D | grep usbmon
```

## Capture

Start the Windows VM with the HD60 S passed through, but do not open capture
software yet. In a host terminal:

```bash
mkdir -p research/traces
./tools/capture-usbmon research/traces/T01-1080p60-start-stop.pcapng 60
```

During the bounded capture, open the device preview, wait ten seconds, and close
it cleanly. The script records the whole USB bus because the device address can
change when the driver resets it.

Raw captures are private and ignored by Git. They may contain device serials,
HDMI content, and vendor firmware traffic.

## Decode and sanitize

```bash
./tools/decode-usb-trace \
  research/traces/T01-1080p60-start-stop.pcapng \
  research/traces/T01-1080p60-start-stop.tsv
```

The decoder exports class-interface transfers and endpoints `0x81`/`0x83`.
Standard descriptor requests are excluded so serial descriptors do not enter
derived fixtures. Inspect decoded payloads before publishing them; class traffic
can still contain sensitive maintenance data if a firmware utility was opened.

Never update firmware or open maintenance/debug property pages while tracing.
